### How to build, run and run tests

From the project root, with Python 3.13 and a running PostgreSQL service:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
# Set DATABASE_URL to a dedicated PostgreSQL test database you can create schemas in.
python -m pytest tests -v --tb=short
```

Full database creation/password instructions are in README, sections
“Create a dedicated test database” and “Configure the connection”. Unit-only
execution requires no database:
`python -m pytest tests/test_detailed_design.py tests/test_architecture.py -v`.
To run the app instead, set DATABASE_URL to a separate fresh application database,
run `python -m src.init_db`, optionally `python -m src.seed_demo`, then
`python -m uvicorn src.main:app --host 127.0.0.1 --port 8000`.
Swagger is at `http://127.0.0.1:8000/docs`. Tests use TestClient and need no
separate Uvicorn process. No frontend build step is required.

```python
from unittest.mock import Mock
import pytest
from fastapi import HTTPException
from sqlalchemy.exc import IntegrityError
from src.main import save, get_db


def test_save_integrity_failure_rolls_back_and_maps_409():
    db = Mock()
    record = object()
    db.commit.side_effect = IntegrityError('UPDATE reservations', {}, Exception('injected constraint failure'))
    with pytest.raises(HTTPException) as caught:
        save(db, record)
    assert caught.value.status_code == 409
    db.rollback.assert_called_once_with()
    db.refresh.assert_not_called()


def test_production_get_db_rolls_back_and_closes_on_error():
    from unittest.mock import MagicMock
    db = MagicMock()
    db.__enter__.return_value = db
    request = Mock()
    request.app.state.session_factory.return_value = db
    dependency = get_db(request)
    assert next(dependency) is db
    failure = RuntimeError('injected request failure')
    with pytest.raises(RuntimeError) as caught:
        dependency.throw(failure)
    assert caught.value is failure
    db.rollback.assert_called_once_with()
    db.__exit__.assert_called_once()
```

Run from the project root, using the actual probe directory:

```bash
PYTHONPATH="$PWD" .venv/bin/python -m pytest -c /dev/null   --confcutdir=/tmp/c06-review-probes   /tmp/c06-review-probes/test_failure_probe.py -v --tb=short
```

## 9 — Record the finding

### F-01 — Missing regression evidence for specified transaction failure paths

**Source:** C05; checklist D4. **Type:** verification gap, not a reproduced
functional defect.

**Engineering claim:** DD-07 and the significant-operations contract specify
rollback/409 on IntegrityError in `save`, and rollback plus session cleanup on
request exceptions in `get_db`.

**Expected:** these significant failure behaviors have direct verification that
exercises the production functions, consistent with C05's DD-derived verification
purpose. Expected behavior is defined in `architecture-and-decisions.md:1528`;
no new framework, coverage percentage or production reliability requirement is added.

**Observed:** baseline tests cover domain rejections but contain no commit-error
injection or direct `save` error assertion. `tests/test_baseline.py:37` overrides
`get_db` with its own rollback wrapper. Passing those tests therefore does not
independently protect the production dependency's cleanup implementation.
The C05 evidence itself acknowledges absent fault injection at lines 704 and 721.

**Evidence:** `src/main.py:41` and `:53`; `tests/test_baseline.py:37`;
`docs/architecture-and-decisions.md:1535`; C05 evidence/limits above.

**Verification performed:** searched all tracked test modules for IntegrityError,
rollback, save and dependency overrides; manually inspected all five test modules
and production functions; ran the complete suite; executed the two temporary
probes reproduced above. Both production behaviors passed under injected mock
failures. Existing passing domain-rejection tests are not equivalent to these probes.

**Result:** **VERIFIED FINDING — regression evidence gap**. No observed evidence
supports claiming that current rollback/409 behavior is broken.
